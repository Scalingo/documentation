Scalingo for MySQL® includes the [common features][databases-features] of
our managed database service, plus MySQL®-specific capabilities such as
SQL modes:

- Scale from a single-node instance to a multi-node, [highly available](#high-availability) cluster
- Choose the right size for your workload, from 512 MB to 512 GB of RAM
- Scale storage from 10 GB to 10 TB
- Scale [concurrent connections](#concurrent-connection-limits) from 30 to 12800
- Configure MySQL® by selecting [SQL modes](#sql-modes)
- Run multiple databases on the same MySQL® instance
- Deploy on Shared or Dedicated Resources (available on request)


## High Availability

Business and Enterprise plans use a high-availability setup with replicated
MySQL® instances to limit service interruptions during maintenance
and platform incidents.
Starter plans use a single instance without high availability.

Depending on the service class, the SLA ranges from 98% to 99.99%.
Choose the [service class and Service Level Agreement][databases-sc]
that fits your use case.

See [High Availability of Scalingo for MySQL®][mysql-ha] for the number
of instances, gateways and SLAs.


## Concurrent Connection Limits

Each plan includes a maximum number of concurrent connections to
maintain stable performance. If you need a higher limit, choose a plan
that fits your workload.

| Architecture model  | Connection limit                   |
|---------------------|------------------------------------|
| Shared Resources    | 60 per GB of RAM                   |
| Dedicated Resources | 100 per GB of RAM, capped at 12800 |

For example, a MySQL® Starter database on Shared Resources with 512 MB RAM
allows up to 30 concurrent connections, while a MySQL® Business database on
Dedicated Resources with 16 GB RAM allows up to 1600 concurrent connections.

{% note %}
To stay within connection limits, we recommend using connection pooling to reuse
connections and reduce the overhead of opening a new connection for each query.
{% endnote %}


## SQL Modes

SQL modes control how MySQL® processes queries and validates data.
You can configure them from the database dashboard.

For the available modes and configuration procedure, refer to *Working with
SQL Modes* for [Shared Resources][sr-sql-modes] or
[Dedicated Resources][dr-sql-modes].
