## English {#en}

### Managed database backups

Backup methods, retention, and restore procedures depend on the database engine, architecture, and service class.
Backups performed by Scalingo are encrypted. PostgreSQL Point-in-Time Recovery (PiTR) provides a recovery window of 7 to 30
days depending on the service class and architecture. Logical backup retention also varies; on Dedicated Resources,
logical backups are customer-managed. See the current [database backup policy][backup-policies] and the restore guide
for your database engine before relying on a particular recovery point or retention period.

### Application and external storage

The filesystem in an application container is temporary: files can be lost when the application restarts or is
redeployed. Database backups do not protect files stored with an external object storage provider. Choose persistent
storage for application files and arrange backups for services that are outside Scalingo's managed database backup
scope. See [file system and file storage][file-storage].

## Français {#fr}

### Sauvegardes des bases de données managées

Les méthodes de sauvegarde, la rétention et les procédures de restauration dépendent du moteur de base de données, de
l'architecture et de la classe de service. Les sauvegardes réalisées par Scalingo sont chiffrées. La restauration
à un instant donné (PiTR) de PostgreSQL offre une fenêtre de récupération de 7 à 30 jours selon la classe de service et
l'architecture. La rétention des sauvegardes logiques varie également ; sur les ressources dédiées, les sauvegardes
logiques sont gérées par le client. Consultez la [politique de sauvegarde des bases de données (en anglais)][backup-policies] en
vigueur et le guide de restauration du moteur concerné avant de compter sur un point de restauration ou une durée de
rétention spécifiques.

### Stockage applicatif et externe

Le système de fichiers d'un conteneur applicatif est temporaire : les fichiers peuvent être perdus lors du redémarrage
ou du redéploiement de l'application. Les sauvegardes de base de données ne protègent pas les fichiers stockés auprès
d'un fournisseur externe de stockage objet. Utilisez un stockage persistant pour les fichiers applicatifs et prévoyez
les sauvegardes des services qui ne font pas partie du périmètre des sauvegardes des bases de données managées par
Scalingo. Consultez la page sur le [système de fichiers et le stockage (en anglais)][file-storage].
